# 나란히 기능명세서

## 1. 문서 목적

이 문서는 **나란히** 서비스가 제공해야 하는 기능을 사용자 관점에서 정리한 기능명세서입니다.

나란히는 한국어 가정통신문을 이해하기 어려운 이주민 학부모가 학교 공지, 준비물, 제출 기한, 행사 일정, 급식, 시간표를 더 쉽게 확인할 수 있도록 돕는 서비스입니다.

이 문서는 다음 기준으로 읽으면 됩니다.

| 구분 | 설명 |
| --- | --- |
| 사용자 기능 | 학부모가 앱에서 직접 사용하는 기능 |
| 시스템 기능 | 공지 수집, OCR, 번역, 일정 추출처럼 백엔드에서 자동으로 처리하는 기능 |
| 연동 기능 | Google, NEIS, Supabase 등 외부 서비스와 연결되는 기능 |
| 예외 처리 | 실패, 데이터 없음, 권한 거부 등 사용자가 막히지 않게 처리해야 하는 기능 |

## 3. 주요 사용자 흐름

### 3.1 학부모 첫 사용 흐름

```text
Google 로그인
  -> 신규 계정 자동 생성
  -> 온보딩 진입
  -> 앱 언어 선택
  -> 자녀 정보 등록
  -> 알레르기/기피 음식 입력
  -> 홈 화면 진입
```

### 3.2 공지 확인 흐름

```text
홈 또는 공지 탭 진입
  -> 선택 자녀 기준 최신 공지 확인
  -> 공지 상세 진입
  -> 카드뉴스 형태로 요약/준비물/해야 할 일/일정/주의사항 확인
  -> 일정이 있으면 Google Calendar 추가 여부 선택
```

### 3.3 급식 확인 흐름

```text
홈 또는 급식 탭 진입
  -> 선택 자녀 학교 기준 오늘 급식 확인
  -> 주간 급식 확인
  -> 알레르기/기피 음식 경고 확인
```

### 3.4 시스템 자동 처리 흐름

```text
학교 공지 정기 수집
  -> 공지 상세 및 첨부파일 수집
  -> 중복 여부 확인
  -> 문서 텍스트 추출 또는 OCR
  -> 요약/카드 생성
  -> 대상 학년/반 추정
  -> 일정 후보 추출
  -> 번역 결과 저장
```

## 4. 상세 기능

## 4.1 인증/계정

### 목적

사용자는 별도 아이디/비밀번호를 만들지 않고 Google 계정으로 간단히 가입하고 로그인할 수 있어야 합니다.

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 1.1.1 | Google OAuth 로그인 | 사용자는 Google 계정으로 회원가입 및 로그인할 수 있다. |
| 1.1.2 | 신규 계정 자동 생성 | 처음 Google 계정으로 접근한 사용자의 서비스 계정이 없으면 신규 사용자 계정을 생성한다. |
| 1.1.3 | Google 이메일 검증 | Google 측 이메일 인증이 완료된 계정만 회원가입 및 로그인을 허용한다. |
| 1.1.4 | 자동 로그인 | 로그인 성공 시 세션을 유지한다. 자동 로그인 유지 기간은 14일로 한다. |
| 1.1.5 | 로그인 실패 처리 | Google 인증 실패 또는 필수 계정 정보를 받아오지 못한 경우 로그인 실패 안내를 표시한다. |
| 1.3.1 | 비회원 접근 제한 | 로그인하지 않은 사용자는 앱 접근이 제한되며 로그인 화면으로 이동한다. |
| 1.3.2 | 로그아웃 | 사용자는 설정 화면에서 로그아웃할 수 있다. 로그아웃 시 현재 세션은 만료된다. |
| 1.4.1 | 다중 기기 로그인 허용 | 사용자는 여러 기기에서 동시에 로그인 상태를 유지할 수 있다. |

## 4.2 첫 이용 온보딩

### 목적

신규 사용자가 앱을 사용하기 전에 필요한 언어와 자녀 정보를 등록하도록 안내합니다.

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 1.2.1 | 온보딩 진입 조건 | 신규 계정으로 처음 로그인한 사용자는 온보딩 화면으로 이동한다. 기존 계정이라도 등록된 자녀 정보가 없으면 온보딩 화면으로 이동한다. |
| 1.2.2 | 앱 언어 설정 | 사용자는 한국어, 중국어 간체, 베트남어 중 앱 기본 언어를 선택할 수 있다. |
| 1.2.3 | 자녀 기본 정보 등록 | 사용자는 자녀의 학교, 학년, 반, 이름 또는 별칭을 입력한다. |
| 1.2.4 | 급식 주의 정보 등록 | 사용자는 자녀의 알레르기 및 기피 음식을 입력할 수 있다. 해당 정보는 선택 입력으로 처리한다. |
| 1.2.5 | 온보딩 완료 조건 | 앱 언어와 필수 자녀 정보가 저장되면 온보딩을 완료하고 홈 화면으로 이동한다. |
| 1.2.6 | 온보딩 미완료 처리 | 온보딩을 완료하지 않은 사용자가 앱에 다시 접근하면 홈 화면이 아니라 온보딩 화면으로 이동한다. |

## 4.3 자녀 관리

### 목적

한 계정에서 여러 자녀를 관리하고, 선택된 자녀 기준으로 공지/급식/시간표 데이터를 볼 수 있어야 합니다.

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 2.1.1 | 다자녀 등록 | 계정당 여러 명의 자녀를 등록할 수 있다. |
| 2.1.2 | 자녀 기본 정보 입력 | 자녀별 학교, 학년, 반, 이름 또는 별칭을 입력한다. |
| 2.1.3 | 급식 주의 정보 입력 | 자녀별 알레르기 및 기피 음식을 직접 입력할 수 있다. |
| 2.2.1 | 자녀 정보 수정 | 등록된 자녀의 학교, 학년, 반, 이름/별칭, 알레르기, 기피 음식을 수정할 수 있다. |
| 2.2.2 | 자녀 삭제 확인 | 자녀 삭제 시 확인 모달을 표시하고, 삭제 후 복구가 어려울 수 있음을 안내한다. |
| 2.3.1 | 현재 자녀 표시 | 홈 화면에 현재 선택된 자녀 정보를 표시한다. |
| 2.3.2 | 자녀 전환 | 등록된 자녀가 2명 이상인 경우 현재 자녀 영역을 통해 다른 자녀로 전환할 수 있다. |
| 2.3.3 | 자녀 기준 데이터 갱신 | 홈, 공지, 급식, 시간표, 캘린더 데이터는 선택 자녀 기준으로 갱신된다. |

## 4.4 공지 수집/처리

### 목적

학교 홈페이지의 공지/가정통신문을 자동 수집하고, 학부모가 이해하기 쉬운 카드 형태로 가공합니다.

### 공지 수집

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 3.1.1 | 대상 학교 정기 수집 | 시스템은 초기 대상 4개 학교의 저장된 공지/가정통신문 게시판 URL을 기준으로 평일 하루 2회 06:30 / 18:00(KST)에 공지 목록을 수집한다. |
| 3.1.2 | 공지 목록 수집 | 공지 목록에서 제목, 게시일, 게시판 ID(bbsId), 게시글 ID(nttId) 등 식별 정보를 수집한다. |
| 3.1.3 | 공지 상세 수집 | 수집한 bbsId, nttId를 기준으로 공지 상세 본문과 첨부파일 정보를 조회한다. |
| 3.1.4 | 첨부파일 수집 | PDF, 이미지, 한글, 워드 등 첨부파일이 있으면 함께 다운로드한다. |
| 3.1.5 | 첨부파일 보관 정책 | 첨부파일 원본은 사용자에게 직접 노출하지 않으며, 비공개 저장소에 30일 보관 후 자동 삭제한다. |
| 3.1.6 | 공지 원본 메타 저장 | 학교 도메인, bbsId, nttId, 원본 URL, 게시일, 제목, 본문, 첨부 메타데이터, 첨부 저장 경로, 수집 시각을 저장한다. |
| 3.1.7 | 수집 실패 로그 저장 | 공지 목록, 공지 상세, 첨부파일 수집 실패 시 실패 시각, 학교, URL 또는 요청 Payload, 오류 내용을 저장한다. |

### 중복 처리

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 3.2.1 | 게시글 식별자 기준 중복 검사 | `school_domain:bbsId:nttId` 형식의 고유 식별값이 동일한 공지는 중복 저장하지 않는다. |
| 3.2.2 | 공지 변경 감지 | 동일 식별값의 공지라도 제목, 본문, 첨부 내용이 변경되면 기존 공지를 최신 내용으로 갱신한다. |
| 3.2.3 | 변경 공지 재분석 | 공지가 갱신되면 OCR, 카드 생성, 번역, 날짜 추출을 다시 수행한다. |
| 3.2.4 | 식별값 추출 실패 처리 | bbsId 또는 nttId를 추출하지 못한 항목은 공지로 저장하지 않고 실패 로그만 기록한다. |

### 문서 분석

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 3.3.1 | OCR 분석 | PDF 스캔본 또는 이미지 첨부에서 텍스트를 추출한다. |
| 3.3.2 | 문서 텍스트 추출 | 한글, 워드, 텍스트형 PDF 등 문서 파일에서 가능한 경우 본문 텍스트를 추출한다. |

### 자동 분석

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 3.4.1 | 구조화 요약 생성 | 공지 내용을 요약, 준비물, 해야 할 일, 일정, 주의사항으로 구조화한다. |
| 3.4.2 | 조건부 카드 생성 | 준비물, 해야 할 일, 일정, 주의사항은 해당 내용이 존재할 때만 카드로 생성한다. |
| 3.4.3 | 대상 판별 | 제목, 본문, OCR/문서 추출 결과에서 학년/반 대상을 자동 추정한다. |
| 3.4.4 | 판별 실패 처리 | 대상 판별 실패 시 전체 학년 공지로 처리해 누락을 방지한다. |
| 3.4.5 | 날짜 추출 | 날짜, 기한, 제출일, 행사일 등 일정성 정보를 추출한다. |
| 3.4.6 | Google Calendar 후보 생성 | 추출된 일정성 정보는 즉시 캘린더에 저장하지 않고 사용자에게 추가 여부를 묻기 위한 후보로 생성한다. |

## 4.5 NEIS 연동

### 목적

학교 정보, 급식, 시간표를 NEIS API에서 조회해 사용자에게 최신 정보를 제공합니다.

### 학교 정보

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 4.1.1 | 학교 홈페이지 주소 조회 | NEIS 학교기본정보 API로 학교 홈페이지 주소를 조회한다. |
| 4.1.2 | 학교 정보 저장 | 학교명, 교육청 코드, 학교 코드, 홈페이지 주소를 저장한다. 교육청 코드와 학교 코드는 NEIS API 조회에 사용한다. |

### 급식

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 4.2.1 | 급식 정기 수집 | NEIS 급식 API로 매일 06:00(KST)에 등록된 자녀의 학교별 오늘/주간 급식 데이터를 조회한다. |
| 4.2.2 | 급식 재시도 수집 | 06:00 정기 수집 실패 시 매일 08:00(KST)에 실패한 학교의 급식 데이터를 재조회한다. |
| 4.2.3 | 급식 저장 | 조회한 급식 메뉴, 날짜, 알레르기 정보를 저장한다. |
| 4.2.4 | 급식 화면 조회 | 사용자가 홈 화면 또는 급식 탭에 진입하면 선택 자녀 학교 기준으로 저장된 급식 데이터를 우선 표시한다. |
| 4.2.5 | 급식 즉시 조회 | 저장된 급식 데이터가 없거나 갱신이 필요한 경우 NEIS 급식식단정보 API로 즉시 조회할 수 있다. |

### 시간표

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 4.3.1 | 시간표 정기 수집 | NEIS 시간표 API로 매일 06:00(KST)에 등록된 자녀의 학교/학년/반 기준 시간표를 조회한다. |
| 4.3.2 | 시간표 재시도 수집 | 06:00 정기 수집 실패 시 매일 08:00(KST)에 실패한 학교/학년/반의 시간표 데이터를 재조회한다. |
| 4.3.3 | 시간표 저장 | 조회한 날짜, 교시, 과목명, 학년, 반 정보를 저장한다. |
| 4.3.4 | 시간표 즉시 조회 | 저장된 시간표 데이터가 없거나 갱신이 필요한 경우 NEIS 시간표 API로 즉시 조회할 수 있다. |

### 실패 처리

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 4.4.1 | NEIS 조회 실패 처리 | 정기 수집, 재시도 수집, 즉시 조회가 실패한 경우 실패 시각, 조회 대상, API 요청 정보, 오류 내용을 저장한다. |
| 4.4.2 | 마지막 정상 데이터 제공 | 급식/시간표 조회 실패 시 마지막으로 저장된 정상 데이터를 우선 제공할 수 있다. |
| 4.4.3 | 데이터 없음 처리 | 해당 날짜의 급식 또는 시간표 데이터가 없는 경우 빈 상태 안내를 제공한다. |
| 4.4.4 | 사용자 오류 안내 | 화면 진입 중 즉시 조회가 실패한 경우 사용자에게 재시도 가능한 오류 메시지를 표시한다. |

| 5.1.2 | 공지 탭 목록 | 공지 전용 탭에서 선택 자녀의 학교 기준 공지 목록을 확인할 수 있다. |
| 5.1.3 | 관련도 우선 노출 | 동일 학년/반 또는 전체 학년 공지를 우선 노출한다. |

| 5.2.2 | 요약 카드 | 공지 전체 맥락과 핵심 내용을 빠짐없이 담은 구조화 요약을 제공한다. |
| 5.2.3 | 준비물 카드 | 공지 내 준비물 정보가 있을 경우에만 생성한다. |
| 5.2.4 | 해야 할 일 카드 | 제출, 확인, 준비 등 행동 정보가 있을 경우에만 생성한다. |
| 5.2.5 | 일정 카드 | 날짜나 행사 일정이 있을 경우에만 생성한다. |
| 5.2.6 | 주의사항 카드 | 주의, 유의, 안내사항이 있을 경우에만 생성한다. |

## 4.7 번역

### 목적

부모가 선택한 언어 기준으로 공지, 급식, 시간표, UI 문구를 제공합니다.

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 6.1.1 | 지원 언어 | 한국어, 중국어 간체, 베트남어를 지원한다. |
| 6.1.2 | 공지 번역 | 공지 내용은 부모의 앱 언어 기준으로 번역해 제공한다. |
| 6.1.3 | 급식/시간표 번역 | 급식 메뉴와 시간표 과목명도 선택 언어 기준으로 제공한다. |
| 6.1.4 | UI 문구 번역 | 앱 내 주요 UI 문구, 버튼, 안내 메시지, 오류 메시지는 선택 언어 기준으로 제공한다. |
| 6.1.5 | 번역 생성 시점 | 공지 번역은 공지 분석 완료 시 생성하고 저장한다. |
| 6.1.6 | 번역 캐싱 | 생성된 번역 결과는 DB에 저장하며, 동일 내용을 매번 재번역하지 않는다. |
| 6.1.7 | 번역 갱신 | 공지 내용이 변경된 경우 기존 번역을 폐기하고 새 내용 기준으로 다시 번역한다. |
| 6.1.8 | 급식/시간표 번역 캐싱 | 급식 메뉴와 시간표 과목명 번역 결과는 재사용할 수 있도록 저장한다. |

## 4.10 Google Calendar 연동

### 목적

공지에서 추출한 행사일, 제출일, 준비 기한을 사용자의 Google Calendar에 쉽게 추가할 수 있게 합니다.

### 공지 기반 일정 감지

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 9.1.1 | 일정 감지 | 공지에서 날짜, 기한, 제출일, 행사일을 인식한다. |
| 9.1.2 | 일정 후보 생성 | 인식된 일정은 사용자 확인을 위해 일정 후보로 생성한다. |
| 9.1.3 | 캘린더 추가 유도 | 일정 후보가 있는 경우 "Google Calendar에 추가할까요?" UI를 표시한다. |
| 9.1.4 | Google Calendar 일정 생성 | 사용자가 추가를 선택하면 해당 공지 일정을 Google Calendar에 생성한다. |
| 9.1.5 | 중복 추가 방지 | 동일 공지의 동일 일정이 이미 추가된 경우 중복 생성하지 않는다. |

### Google Calendar 권한

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| 9.2.1 | 연동 시작 | 사용자는 공지 일정 추가 시점 또는 설정 화면에서 Google Calendar 연동을 시작할 수 있다. |
| 9.2.2 | 권한 동의 | Google Calendar 일정 생성에 필요한 권한 동의를 요청한다. |
| 9.2.3 | 권한 거부 처리 | 권한을 거부해도 앱 사용은 가능하며, Google Calendar 추가 기능만 제한된다. |
| 9.2.4 | 연동 상태 저장 | 시스템은 Google Calendar 연동 여부와 생성된 캘린더 `event_id`를 저장해 중복 추가를 방지한다. |
| 9.2.5 | 연동 해제 | 사용자는 설정 화면에서 Google Calendar 연동을 해제할 수 있다. |

| 11.2.3 | 공지 분석 실패 처리 | 공지 OCR 또는 분석 실패 시 최소 정보만 노출하거나 카드 생성을 제외한다. |
| 11.2.4 | Google Calendar 저장 실패 처리 | 캘린더 저장 실패 시 실패 안내 후 재시도를 유도한다. |

## 5. MVP 우선순위 제안

초기 개발에서는 모든 기능을 한 번에 만들기보다, 아래 순서로 구현하는 것이 좋습니다.

| 우선순위 | 기능 묶음 | 이유 |
| --- | --- | --- |
| 1 | Google 로그인, 온보딩, 자녀 등록 | 사용자를 식별하고 자녀 기준 데이터를 보여주기 위한 기본 조건 |
