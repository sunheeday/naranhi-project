# 사업 G — 시간표 시각화 · 방과후 일정 · 알림 설계서

작성일: 2026-08-30
상태: 설계안 (미구현)
상위 문서: [기능명세서-자녀-개인일정.md](../../기능명세서-자녀-개인일정.md) (개인 일정 부분의 원본 명세)

## 1. 무엇을 만드는가

학부모가 **자녀의 하루 전체**(학교 수업 + 방과후 활동)를 한 화면에서 보고,
**하교 · 방과후 · 가정통신문 마감**을 자기 언어로 알림받게 한다.

지금은 학교 수업만, 그것도 `1교시 국어` 형태의 교시 목록만 보인다.
시계 시각이 없고, 방과후가 없고, 알림이 없다.

### 세 덩어리

| 덩어리 | 내용 |
| --- | --- |
| **G1 · 교시 시각** | 학교별 교시 시각표를 확보해 `09:00–09:40 국어` 로 표시하고 하교 시각을 계산한다 |
| **G2 · 방과후 일정** | 부모가 태권도·학원 등 주간 반복 일정을 등록해 학교 시간표와 함께 본다 |
| **G3 · 알림** | 하교 · 방과후 · D-day 세 알림을 웹 푸시로 보낸다. 각각 켜고 끌 수 있다 |

## 2. 조사로 확정된 사실

설계의 근거다. 추측이 아니라 2026-08-30 실측이다.

| 사실 | 근거 |
| --- | --- |
| NEIS 시간표에 **시계 시각이 없다** | 응답 필드가 `ALL_TI_YMD`(날짜) `PERIO`(교시) `ITRT_CNTNT`(과목)뿐 |
| NEIS는 **그날 마지막 교시를 알려준다** | 학년·반별 시간표를 그대로 주므로 `max(period)` 가 그날 마지막 교시 |
| 학교 홈페이지 일과표 발견율 = **5곳 중 1곳** | 우리 학교 5곳의 메인 + 사이트맵 전수 조사. 초등 3곳은 전부 없음 |
| 일과표는 **글이 아니라 그림**이다 | 부천부흥중 일과표 페이지는 본문 1,782자에 교시 0개. 내용은 `alt='일과표 이미지'` PNG |
| 찾히면 **품질은 완벽** | 등교·1~7교시·점심·종례·요일별 교시 수까지 전부 |
| 홈페이지는 **JS 리다이렉트 껍데기** | 최초 HTML 800~3,900자, `<a>` 0개. 크롤러가 이미 추적 중 |
| 앱은 **PWA이고 서비스워커가 없다** | `public/` 에 서비스워커 파일 없음. 네이티브 래퍼 의존성 없음 |

## 3. 핵심 결정

### 결정 ① 교시 시각 확보 경로 — **홈페이지 + 표준값 2단** (가정통신문 경로 제외)

세 후보 중 둘만 쓴다.

- **채택 · 1단 홈페이지**: 찾히면 품질이 완벽하다. 발견율은 낮지만 비용이 싸다(1년 1회).
- **기각 · 2단 가정통신문**: 학기 초에 한 번 올까 말까 하고, 시험용 단축 시정표와 구분이 어렵다.
  틀린 시정표를 잡으면 하교 시각이 통째로 어긋난다. **도박이라 뺀다.**
- **채택 · 3단 표준값 + 부모 수정**: 못 찾는 것이 기본값이므로 이쪽이 실질적 주력이다.

### 결정 ② 저장 형태 — **교시별 행** (파라미터 계산 아님)

실측 일과표가 규칙적이지 않다. 부천부흥중은 4교시가 12:40에 끝나고 점심 뒤 5교시가
13:30에 곧바로 시작한다(쉬는 시간 0분). 반면 5→6교시, 6→7교시는 10분씩 쉰다.
"시작 시각 + 수업 길이 + 쉬는 시간"으로는 이 예외를 담을 수 없다.

→ `school_bell_schedules(school_id, period, start_time, end_time)` 로 **교시마다 한 행**.
표준값도 같은 형태로 미리 채워 넣는다. 읽는 쪽 코드가 경로를 구분할 필요가 없어진다.

### 결정 ③ 요일별 교시 수는 **저장하지 않는다**

부천부흥중 일과표에 `월6 화7 수5 목7 금6` 이 적혀 있지만 저장하지 않는다.
**NEIS가 그날 그 반의 실제 시간표를 이미 주기 때문**이다. 저장하면 두 개의 진실이 생기고,
시험·행사로 단축 수업할 때 NEIS 쪽만 맞고 저장본은 틀린다.

→ **하교 시각 = 그날 NEIS 마지막 교시의 `end_time` + 종례 10분.**

### 결정 ④ 부모 수정은 **1교시 시작 시각 하나만**

부모에게 7줄짜리 표를 채우게 하면 아무도 채우지 않는다.
"우리 학교는 8시 50분에 시작해요" 한 번만 받고 **전체를 통째로 민다**.

→ `children.bell_offset_minutes`. 학교 공용 데이터(`school_bell_schedules`)는
부모가 절대 수정하지 못한다 — 한 부모의 수정이 같은 학교 다른 부모에게 번지면 안 된다.

### 결정 ⑤ 알림 문구는 **고정 문구 + 파라미터**. AI 번역을 쓰지 않는다

`notif_dismissal_body = "{child} 오늘 {time}쯤 끝나요"` 를 9개 언어 파일에 미리 넣고,
발송 시점에 `{child}` `{time}` 만 끼운다.

AI 번역을 붙이면 알림 한 건마다 비용·지연·실패 가능성이 생긴다. 알림은 **짧고 정형**이라
번역할 이유가 없다. 자녀 이름은 부모가 입력한 값이므로 번역하지 않고 그대로 쓴다.

### 결정 ⑥ 발송은 **계획(planner) → 발송(sender)** 2단

- `notification_planner` — 매일 05:00 KST. 그날 보낼 알림을 전부 계산해 `notification_outbox` 에 넣는다.
- `notification_sender` — 5분마다. `send_at` 이 지난 것을 집어 실제로 보낸다.

한 잡으로 합치면 "왜 안 왔는지"를 추적할 수 없다. 나눠 두면 outbox 를 보는 것만으로
「계획이 안 됐다」와 「계획은 됐는데 발송이 실패했다」가 구분된다.

### 결정 ⑦ 화면은 **기존 카드 뷰 확장**. 시간축 그리드로 바꾸지 않는다

[기능명세서-자녀-개인일정.md](../../기능명세서-자녀-개인일정.md) §2 결정 ①(A안)을 그대로 따른다.
요일 카드 안에서 교시 리스트에 시각을 붙이고, 그 아래에 개인 일정 구획과 하교 표시를 얹는다.

시간축 그리드 전환은 별도 과제로 남긴다.

## 4. 데이터 모델

새 테이블 4개 + 기존 컬럼 1개.

```
school_bell_schedules   학교 × 교시 → 시각      (학교 공용, 관리자만 수정)
child_personal_schedules 자녀 × 요일 → 방과후    (부모 소유)
push_subscriptions      사용자 → 브라우저 구독
notification_preferences 사용자 → 알림 3종 on/off + 조용한 시간
notification_outbox     발송 예약 + 결과
children.bell_offset_minutes  자녀별 시각 보정 (기본 0)
```

### 소유권 · 권한 원칙

| 테이블 | 부모 | 관리자 |
| --- | --- | --- |
| `school_bell_schedules` | **읽기만** | 읽기/쓰기 |
| `child_personal_schedules` | 자기 자녀만 CRUD | — |
| `push_subscriptions` | 자기 것만 CRUD | — |
| `notification_preferences` | 자기 것만 | — |
| `notification_outbox` | **접근 불가** | 읽기 |

`notification_outbox` 는 RLS 켜고 정책 0개 — 서버(`service_role`)만 접근한다.
`app_jobs` 와 같은 취급이다.

## 5. 하교 시각 계산

```
그날 시간표(NEIS) → 마지막 교시 N
school_bell_schedules[school_id][N].end_time
  + children.bell_offset_minutes
  + 종례 10분
= 하교 시각(추정)
```

**항상 "쯤"을 붙여 표시한다.** 종례 10분은 상수이고 학교마다 다르며, 표준값 경로에서는
1교시 시작조차 추정이다. 정확한 척하면 틀렸을 때 신뢰를 잃는다.

시간표를 못 가져오는 학교(`UnsupportedTimetableError`)는 하교 시각을 표시하지 않고
알림도 만들지 않는다.

## 6. 알림 3종

| 종류 | 언제 보내나 | 조건 |
| --- | --- | --- |
| **하교** | 하교 시각 30분 전 | 시간표가 있고, 그날 수업이 있는 날 |
| **방과후** | 일정 시작 30분 전 | 그 요일에 등록된 개인 일정 |
| **D-day** | 마감 하루 전 08:00 | `school_events.event_kinds` 에 `deadline` 포함 |

### 공통 규칙

- **조용한 시간** 21:00–07:00 에는 보내지 않는다. 그 시간에 걸리면 건너뛴다(미루지 않는다).
- **중복 방지**는 `notification_outbox.dedupe_key` 유니크 제약으로 한다.
  `kind:child_id:target_date:ref` 형태. 재실행해도 두 번 안 간다.
- **주말·공휴일**에는 하교 알림을 만들지 않는다(NEIS 시간표가 비어 있으면 자동으로 그렇게 된다).

### D-day 의 위험

마감일은 AI가 공지에서 읽어낸 값이라 틀릴 수 있다.
→ 문구를 단정형으로 쓰지 않는다. "마감입니다"가 아니라
**"내일 마감인 것 같아요 — 공지를 확인해 주세요"** 로 하고 공지 링크를 함께 보낸다.

## 7. 웹 푸시의 한계 (명시)

- **안드로이드 크롬**: 정상 동작.
- **아이폰 사파리**: iOS 16.4 이상 **그리고 홈 화면에 추가한 경우에만** 동작한다.
  그냥 사파리로 열어 본 부모는 **절대 받지 못한다.**

이 한계는 코드로 없앨 수 없다. 대신 두 가지를 한다.

1. 아이폰 + 홈 화면 미추가 상태를 감지해 **부모 언어로 추가 방법을 안내**한다.
2. **구독률을 측정**한다 — 로그인 사용자 대비 유효 구독 수. 이 값이 낮으면
   그때 카카오 알림톡 등 다른 경로를 검토한다. 지금은 추측으로 정하지 않는다.

## 8. 홈페이지 일과표 수집 (G1 · 1단)

기존 크롤러 부품을 재사용한다. 새로 만드는 것은 프롬프트와 조립뿐이다.

```
schools.homepage_url
  → HomepageClient.fetch (JS 리다이렉트 추적)     [기존]
  → link_extractor.extract_links                  [기존]
  → GeminiFinder.choose_bell_schedule_page        [신규 — 프롬프트만 다름]
  → 그 페이지 fetch
      → 본문 텍스트에 교시+시각이 있으면 텍스트 파싱
      → 없으면 본문 이미지를 Gemini 로 읽어 JSON   [기존 이미지 파이프라인 재사용]
  → school_bell_schedules 에 source='homepage', confirmed_at=null 로 저장
  → 관리자 콘솔에 «승인 대기» 로 표시
```

### 반드시 사람이 승인한다

AI가 그림을 잘못 읽으면 하교 시각이 통째로 틀리고, 그 알림이 부모에게 간다.
**학교가 8개뿐이므로 8번 확인하면 끝난다.** 자동 승인은 넣지 않는다.

`confirmed_at is null` 인 일과표는 화면·알림 어디에서도 쓰지 않는다.
승인 전에는 표준값이 계속 쓰인다.

### 실행 방식

스케줄러로 돌리지 않는다. 일과표는 1년에 한 번 바뀐다.
**관리자 콘솔의 버튼**으로 학교 하나씩 돌린다.

## 9. 범위 밖 (v2)

- 시간축 그리드 전환
- 일회성(특정 날짜) 개인 일정, 주말 표시, 방학·시험 기간 예외

- 알림 시각을 부모가 조절 (v1은 30분 전 고정)
- 학교 방과후·돌봄·늘봄 프로그램 자동 수집
  (조사 중 해당 게시판이 표준 메뉴로 존재함을 확인 — 나중에 붙일 여지가 있다)
- 카카오 알림톡 등 웹 푸시 외 경로

## 10. 사람이 해줘야 하는 것

구현 중 막히는 지점. 미리 적어 둔다.

| 필요한 것 | 왜 | 누가 |
| --- | --- | --- |
| VAPID 키쌍 생성 후 **비밀키를 Secret Manager 에** | 웹 푸시 서명용. 공개키는 노출돼도 되나 비밀키는 서버 전용 | 키 생성은 로컬에서 가능, 등록은 권한 필요 |
| 마이그레이션 0048–0050 **수동 적용** | GitHub Actions 가 자동 적용하지 않는 관례 | 대시보드 SQL Editor |
| Cloud Scheduler **2개 추가** | planner(일 1회) + sender(5분) | GCP 권한 |

`SUPABASE_DB_PASSWORD` 는 저장소·환경 어디에도 넣지 않는다 —
넣는 순간 이미 손으로 적용한 0038–0047 이 재적용된다.
